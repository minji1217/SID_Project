Transformer V1 · 그림으로 보는 학습과 추론

우리 V1이 기록 SID와 후보 SID를 어떻게 토큰으로 넣고, 어떻게 점수를 내고, 어떻게 학습·추론하는지 토큰 단위로 그렸습니다. 기사 · SID는 실제 데이터, 확률 · 점수는 설명용 숫자입니다. 구조는 T5 encoder-decoder를 단순화했습니다(임베딩 공유 · 위치 표현 등 세부는 Transformer 저장소 코드 기준 확인 필요).

2. encoder: 기록 기사 → 토큰 → 기록 메모 M

기록 기사 하나 = 토큰 4개(c1 c2 c3 c4). SEP 없이 이어 붙여 최대 50기사 × 4 = 200토큰. 토큰마다 자기 자리 전용 임베딩 표에서 256차원 벡터를 꺼내고, encoder가 토큰끼리 서로 참고해 맥락이 섞인 “기록 메모 M”을 만듭니다.

  • SEP 없이 4개 묶음을 아는 방법: 토큰마다 자리별 임베딩 표(E1~E4)에서 꺼내므로 벡터에 “나는 c1 토큰” 같은 종류 정보가 들어 있고, 순서가 항상 c1 → c2 → c3 → c4로 반복되어 c1이 나오면 새 기사 시작입니다. 토큰 사이 거리(T5 relative position)도 함께 반영됩니다. 탐색 1단계에서 SEP 사용 · 미사용을 비교해 미사용이 뽑혔습니다.
  • encoder 출력: 입력 토큰 하나당 256차원 벡터 하나 → 기록 50개면 최대 200개(묶음 단위로 [문제 수, 200, 256]). PAD 자리는 mask로 무시합니다.

3. decoder: 후보 하나를 한 자리씩 채점

후보 SID의 앞자리를 넣어 주고([BOS, c1, c2]), 출력 세 자리에서 c1 · c2 · c3의 확률을 냅니다. 각 head는 자기 코드북 전체(25 · 128 · 512칸)에 대한 확률을 내고, 그중 후보의 실제 코드 칸만 읽어 log를 더합니다.

3-1. cross-attention: 차원이 어떻게 맞나

decoder 쪽은 3토큰(BOS · c1 · c2), encoder 출력 M은 최대 200토큰이라 길이가 다릅니다. 하지만 둘 다 토큰마다 256차원이라 곱셈이 맞물립니다. decoder가 Q(질문)를, M이 K(열쇠) · V(내용)를 만들고, Q · Kᵀ로 3 × 200 점수를 낸 뒤 그 가중치로 V를 섞으면 다시 3 × 256이 됩니다. head는 8개라 256을 32차원씩 나눠 계산하고 다시 이어 붙입니다(T5 설정에 따라 head당 차원은 다를 수 있음).

3-2. decoder 안에서: BOS → BOS c1 → BOS c1 c2

encoder 출력은 기록 토큰 수만큼의 256차원 벡터입니다(기록 3기사면 12개, 50기사면 200개). decoder는 개념상 한 자리씩 [BOS] → [BOS, c1] → [BOS, c1, c2]로 늘려 가며 다음 자리를 맞히지만, 실제로는 세 자리를 한 번에 넣고 mask로 “앞자리까지만 보기”를 지켜 같은 결과를 한 번에 냅니다.

3-4. c1 자리(입력 21) 한 줄만 따라가기 — 행렬 그림

3-3절과 같은 숫자로, decoder의 c1 자리(입력 토큰 21, 맞힐 것은 c2) 한 줄이 self-attention에서 BOS와 c1을 섞고, 그 벡터를 질문(Q)으로 cross-attention에서 encoder 출력만 보는 과정을 그렸습니다.

3-5. cross-attention 다음: FFN · 2층 · head

cross-attention 출력에 원래 입력을 더하고(residual) 정규화한 뒤 FFN을 거치면 decoder 1층이 끝납니다. 같은 구조를 한 번 더(2층) 거친 최종 출력(자리마다 256차원)을 자리별 head에 넣습니다. head는 256차원을 그 자리 코드 개수만큼의 점수로 바꾸는 행렬(Linear)입니다: head1 = 256 × 25, head2 = 256 × 128, head3 = 256 × 512. 열 하나가 코드 하나이고, 점수 = 출력 벡터와 그 열의 내적 → softmax → 후보 코드 칸의 확률을 읽습니다.

log를 쓰는 이유: 곱이 덧셈이 됨

후보 SID 전체가 나올 확률 = 세 자리 확률의 곱: P(21-117-147) = 0.40 × 0.30 × 0.03 = 0.0036. log를 씌우면 S = ln 0.0036 = L1 + L2 + L3 = −0.92 − 1.20 − 3.51 = −5.63. 작은 확률을 계속 곱해 0으로 뭉개지는 문제가 없고, log는 크기 순서를 바꾸지 않아 S가 큰 후보 = SID 전체 확률이 큰 후보입니다. 확률이 1 이하라 L은 항상 0 이하이며 0에 가까울수록 확률이 높습니다.

왜 자연로그(밑 e)인가

  • softmax와 짝: softmax가 e의 거듭제곱을 쓰므로 ln을 씌우면 e가 사라져 ln P(21) = 점수₂₁ − ln(e^점수₀ + … + e^점수₂₄)라는 빼기식이 됩니다. PyTorch의 log_softmax · CrossEntropyLoss도 자연로그 기준입니다.
  • 미분이 가장 간단: loss = −ln P(정답)을 점수로 미분하면 Pₖ − (정답이면 1, 아니면 0). 정답 칸(0.40 − 1 = −0.60)은 점수를 올리고, 오답 칸(+0.30)은 내리는 방향입니다. 다른 밑이면 1/ln 2 같은 상수가 붙습니다.
  • 밑을 바꿔도 순위는 같음: 모든 값에 같은 상수가 곱해질 뿐이라 후보 순서 · Top-1 · MRR은 그대로이고, loss 크기만 상수배로 달라집니다.

4. 후보 5개를 같은 방식으로 채점

같은 기록 메모 M을 두고 decoder를 후보마다 한 번씩(5번) 돌립니다. 후보끼리는 서로를 보지 않습니다(attention 없음). 각 후보의 S는 그 후보의 토큰 3개와 M만으로 정해지므로, 5개를 하나씩 돌리든 묶어서(batch) 한꺼번에 돌리든 결과가 같습니다. 후보들이 처음 비교되는 곳은 학습 때의 softmax입니다.

8. TIGER 원문 추론: beam search는 어떻게 동작하나

beam search는 후보 목록 없이 SID를 직접 만들어 내는 추론 방식입니다. 자리마다 코드북 전체(우리 head는 25 · 128 · 512칸, 논문은 256칸)의 확률을 보고, 앞자리부터 이어 붙인 누적 log 확률이 높은 B개(beam 크기)만 남기며 진행합니다. 모든 조합(우리 기준 25 × 128 × 512 ≈ 164만)을 다 볼 수 없어서 중간에 계속 잘라냅니다.

  1. Step 1: c1 head의 확률 중 상위 B개를 남김
  2. Step 2: 남은 각각에 c2 코드북 전체를 붙여 보고(B × 128가지), 누적 log 확률 상위 B개만 남김
  3. Step 3: 같은 방식으로 c3까지 붙여 최종 SID B개 (논문은 4번째 충돌 토큰까지)
  4. 결과: 생성한 SID를 실제 아이템으로 바꿔 추천. 없는 SID면 hallucination → 버리고 다음 순위 사용

같은 확률인데 후보 채점과 결과가 다른 이유

10. V1 + level 가중치: 어떻게 하나 (예시)

모델은 V1 그대로이고, 점수를 더하는 방식만 바꿉니다. 재학습은 없습니다. V1 checkpoint가 문제마다 저장해 둔 후보별 L1 · L2 · L3(test_candidate_scores.parquet)를 다시 더할 뿐입니다.

점수식
V1S = 1·L1 + 1·L2 + 1·L3
V1 + level 가중치S′ = 1·L1 + 0.5·L2 + 0.1·L3

예시: 정답이 새 기사라 c3 확률이 낮은 문제 (설명용 숫자)

정답 A는 새 기사라 모델이 그 c3를 거의 본 적이 없어 L3가 매우 낮고(−4.80), 오답 B는 train에서 많이 본 기사라 c2는 덜 맞지만 c3 확률이 높습니다(−2.00).

후보L1L2L3V1: S = L1+L2+L3가중치: S′ = L1 + 0.5·L2 + 0.1·L3
A 정답 (새 기사)−0.92−1.20−4.80−6.92 (4위)−0.92 + 0.5×(−1.20) + 0.1×(−4.80) = −2.00 (1위)
B 오답 (train에서 많이 본 기사)−0.92−1.90−2.00−4.82 (1위)−0.92 + 0.5×(−1.90) + 0.1×(−2.00) = −2.07 (2위)
C 오답−1.61−1.20−3.20−6.01 (2위)−1.61 + 0.5×(−1.20) + 0.1×(−3.20) = −2.53 (3위)
D 오답−2.30−1.61−3.00−6.91 (3위)−2.30 + 0.5×(−1.61) + 0.1×(−3.00) = −3.41 (4위)
E 오답−3.00−2.30−3.50−8.80 (5위)−3.00 + 0.5×(−2.30) + 0.1×(−3.50) = −4.50 (5위)
  • V1: B가 1위(−4.82), 정답 A는 4위(−6.92) → 오답. c3 점수 차(−4.80 vs −2.00)가 c2 점수 차를 뒤집어 버림.
  • 가중치: c3를 0.1만 반영하니 c3 차이가 0.28로 줄고, c2에서 앞선 A가 1위(−2.00 vs −2.07) → 정답.
  • 즉 “새 기사에 잘 일반화되지 않는 기사 수준 코드(c3)”의 영향을 줄이고, 카테고리 · 주제 수준(c1 · c2) 판단을 더 믿는 방식입니다.

  2. α1 = 1 고정, α2 ∈ {0, 0.25, 0.5, 0.75, 1.0, 1.25, 1.5} × α3 ∈ {0, 0.1, 0.25, 0.5, 0.75, 1.0} = 42가지를 validation half에서 Top-1로 비교
  3. 가장 좋은 (1, 0.5, 0.1)을 골라 test에 한 번 적용
