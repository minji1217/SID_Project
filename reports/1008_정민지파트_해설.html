B-2. 원래 설계와 다른 점 — 해석할 때 꼭 알아야 할 것

원래 설계에서 c2는 사건 유형입니다. 같은 사건의 기사는 그 기사들의 인코더 출력 평균 z(E)로 정한 같은 c2를 받습니다. UNI SID를 만든 코드는 RQ-VAE·SID 쪽에서 두 가지가 다릅니다.

원래 설계UNI를 만든 코드
① 학습 중 c2같은 사건 기사들은 z(E) = mean(h)의 argmin으로 같은 c2기사마다 각자 r1 = h − q1의 argmin → 같은 사건 c2 일치율 74%
② 새 사건(validation-only) c2첫 기사 h로 정하고 고정. 이후 기사는 상속, 개체 집합·최신성만 갱신그 사건 validation 기사 전체 h의 평균 (영향 159개 = 5.1%)
그래서 2~8장의 c2는 설계상의 “사건 유형”이라기보다 “같은 카테고리 안에서 임베딩이 가까운 기사 묶음(주제 묶음)”으로 읽는 것이 정확합니다. 이 평가들은 “SID 계층이 기사 내용의 유사도 구조를 따르는가”를 보여 주며, “c2가 사건 단위로 묶였는가”는 사건 c2 일치율(74%)이 따로 답합니다. c2를 사건 단위로 다시 학습한 EventC2(일치율 100%)는 별도 실험입니다.

2장 · 정성평가 — 설계와 판정 기준

정성근거 확인
숫자 말고 사람이 기사를 직접 읽었을 때, 같은 SID로 묶인 기사들이 정말 비슷한지 확인했습니다. “같은 사건인가”가 아니라 기사 전체 내용이 얼마나 비슷한가를 봤습니다.

목적

숫자 지표가 놓칠 수 있는 “실제로 읽었을 때 비슷한가”를 사람이 직접 확인합니다. 같은 SID 그룹이 하나의 묶음으로 타당한지를 그룹 단위로 판정합니다.

실험 동작 방식

표본 뽑기 — “그룹 먼저(group-first)” 방식 (step2/step2_sample.py, seed 42)

쌍(pair)을 무작위로 뽑지 않고 그룹을 먼저 뽑은 뒤 그 그룹 기사 전부를 읽었습니다. collision은 그룹 현상이기 때문입니다. 같은 SID 기사 6개를 쌍으로 흩어 뽑으면 “이 6개가 한 덩어리인 게 타당한가”에 답할 수 없고, 크기 k 그룹은 쌍을 k(k−1)/2개 만들어 큰 그룹이 과하게 뽑힙니다.

(나) Jaccard = 겹치는 단어 수 ÷ 둘을 합친 단어 수

단어가 몇 번 나왔는지는 보지 않고, 나왔나 안 나왔나만 봅니다.

A = {cecilie, 20, år, og, fra, hårlev}, B = {cecilie, 21, år, og, fra, hårlev}
겹침 = {cecilie, år, og, fra, hårlev} → 5개 · 합침 = 7개 (20과 21이 하나씩 더) → Title Jaccard = 5 ÷ 7 = 0.714
본문도 같은 방식: A의 서로 다른 단어 80개, B 99개, 겹침 28개, 합침 151개 → Body Jaccard = 28 ÷ 151 = 0.185

Jaccard의 약점: 전혀 무관한 Different 쌍(Side 9 인물 vs 호텔 파산)도 Body Jaccard가 0.123입니다. og(그리고), i(~에), på(~위에), er(~이다) 같은 흔한 단어가 어느 본문에나 있어서 겹침으로 세어지기 때문입니다. 이 점을 보완하는 것이 TF-IDF입니다.

(다) TF-IDF cosine = 특징 단어가 얼마나 겹치나

  1. TF (그 기사 안에서 몇 번 나오나): 많이 나올수록 그 기사에서 중요한 단어입니다. 다만 sublinear tf로 1 + log(횟수)를 써서, 10번 나온 단어가 1번 나온 단어보다 10배가 아니라 약 3.3배만 커지게 합니다.
  2. IDF (전체 9,338개 본문 중 몇 개에 나오나의 반대): 드문 단어일수록 큽니다. 계산식은 ln((1 + 9,338) ÷ (1 + 나온 기사 수)) + 1.

6장 · 정량평가 2 — 임베딩 cosine

정량근거 확인
prefix를 더 많이 공유할수록 RQ-VAE가 보는 임베딩 공간에서도 더 가까운지 봤습니다. 여기서는 Prefix-1을 추가해 공유 prefix 0 → 1 → 2 → 3의 4단계로 봅니다.

목적

5장이 단어 수준이라면, 6장은 RQ-VAE가 실제로 보는 임베딩 공간에서 SID 계층이 거리 구조를 따르는지 봅니다. Prefix-1을 더해 공유 prefix 0→1→2→3의 네 단계로 봅니다.

실험 동작 방식

두 가지 cosine

Original embedding cosine

RQ-VAE에 들어가기 전, 두 기사의 E5 768차원 벡터끼리 cosine. “원래 얼마나 가까웠나”

Reconstruction cosine

각 기사의 SID로 복원한 벡터 x̂ = decoder(Q1[c1] + Q2[c2] + Q3[c3])끼리 cosine. “SID만 남겼을 때 얼마나 가까운가”

쌍과 계산 (step6/, step6_prefix1/)

  • 5장과 같은 쌍 집합에 Prefix-1(c1만 같고 c2 다름) 50,000쌍을 그룹 균형으로 추가했습니다.
  • 그래프의 점은 평균, 띠는 1사분위~3사분위 범위입니다.

그래프 읽는 법

  • 가로축은 공유 prefix 수(0 = Different, 1, 2, 3 = Prefix-3), 세로축은 cosine입니다.

  • 두 선이 모두 오른쪽으로 갈수록 올라가면(단조 증가) “prefix를 더 공유할수록 더 가깝다”는 뜻입니다. 주황 선이 파란 선보다 위에 있는 것은 위의 거리 압축 때문입니다.

결과 분석 방법과 해석

읽는 법

  • Original이 0→1→2→3으로 계속 오릅니다. SID를 만들기 전부터, 긴 prefix를 공유하게 될 기사들이 원래 임베딩 공간에서도 가까웠다는 뜻입니다. RQ-VAE가 원래 유사도 구조를 따라 코드를 나눴다는 근거입니다.
  • Prefix-3 복원 cosine = 1.0은 성능 근거가 아닙니다. c1·c2·c3가 같으면 decoder 입력이 같아서 복원 벡터가 완전히 같아지는, 구조상 자동으로 나오는 값입니다. 핵심 근거는 그 앞 3단계 0.9294 < 0.9522 < 0.9810입니다.
  • 복원 공간에서는 Different도 0.93으로 높습니다. 128차원 코드로 압축했다가 펴면서 벡터들이 서로 가까워진 것이므로, 절댓값이 아니라 단계 간 차이를 봐야 합니다.

설계 관점에서 의미

  • 원본 cosine이 네 단계 모두에서 오른다는 것은, RQ-VAE가 원래 임베딩 공간의 거리 구조를 따라 c1 → c2 → c3를 나눴다는 뜻입니다. 설계의 coarse-to-fine 계층과 맞습니다.
  • 특히 Prefix-1(c1만 같음, 0.818)이 Different(0.799)보다 높아, 카테고리로 고정한 c1도 임베딩상 의미 있는 묶음입니다.

한계 · 주의

  • Prefix-3 복원 cosine 1.0은 구조상 자동이라 근거에서 뺍니다.
  • 복원 공간은 압축으로 거리가 좁혀져 절댓값을 원본과 직접 비교하면 안 됩니다.
  • 원본 임베딩은 모델 입력 공간이므로 5장(본문)보다 “자기 확인”에 가깝습니다.

정량근거 확인
5·6장이 “기사 쌍”을 봤다면, 7장은 기사 하나를 SID로 압축했다가 되살렸을 때 원본 방향을 얼마나 유지하는지를 봤습니다.
원본 x (E5 768)→encoder 768→128→z = Q1[c1] + Q2[c2] + Q3[c3]→decoder 128→768→x̂

읽는 법

  • 768차원을 코드 3개(카테고리 + 128개 중 하나 + 512개 중 하나)로 줄여도 방향의 대부분이 남습니다. c3(서술 잔차)가 기사 고유의 세부를 상당 부분 담는다는 뜻입니다.
  • SID만으로 기사 임베딩을 되살릴 수 있어야 생성형 추천(SID 생성 → 기사 그라운딩)이 성립하므로, 원래 설계의 전제 조건을 확인한 실험입니다.

8장 · 정량평가 4 — KNN

정량코드로 재현 확인
5~6장은 “SID가 같으면 가까운가”였고, 8장은 방향을 뒤집어 “원본 E5에서 실제로 가까운 기사들이 SID도 공유하는가”를 봤습니다.

목적

2~6장은 “SID로 묶은 뒤 비슷한지” 봤습니다. 8장은 방향을 뒤집어 “원본 임베딩에서 실제로 가까운 기사들이 SID도 공유하는지”를 봅니다. 두 방향이 모두 성립해야 SID가 임베딩 구조를 제대로 옮겼다고 할 수 있습니다.

실험 동작 방식

방법

  1. Train 기사 9,738개의 E5 벡터를 길이 1로 정규화합니다.
  2. 기사 A 하나를 기준(anchor)으로 잡고, 자기 자신을 뺀 나머지 9,737개와 cosine을 계산합니다.
  3. cosine이 가장 높은 10개를 A의 이웃으로 고릅니다.
  4. 이웃 10개 각각이 A와 same c1 / same (c1,c2) / same (c1,c2,c3)인지 셉니다.
  5. 9,738개 기사 전부에 반복해 97,380쌍(= 9,738 × 10)에서 비율을 냅니다.

무작위 기준 (random baseline)

Train에서 기사 2개를 아무렇게나 뽑았을 때 같은 prefix일 확률입니다. 같은 prefix 그룹마다 “그 안에서 만들 수 있는 쌍 수”를 더해 전체 쌍 수로 나눕니다.

예) 기사 100개, c1=0이 50개·c1=1이 30개·c1=2가 20개라면 같은 c1 쌍 = 50·49/2 + 30·29/2 + 20·19/2 = 1,225 + 435 + 190 = 1,850. 전체 쌍 = 100·99/2 = 4,950. 무작위 기준 = 1,850 / 4,950 = 37.4%

9장 · 정량평가 5 — NRMS (추천 성능)

정량코드·결과 확인Test 기준발표 후 수정
추천 모델 NRMS를 원 논문 구조 그대로 두고 기사 표현만 E5 · SID · 제목 · 섞은 SID로 바꿔, “SID로 압축해도 추천에 필요한 정보가 남는가”를 봤습니다.

목적

2~8장이 SID 자체의 품질이라면, 9장은 그 SID를 추천 모델에 넣었을 때 추천에 필요한 정보가 얼마나 남는지를 봅니다. 같은 모델에서 기사 표현만 바꿔 비교하는 통제 실험입니다.

실험 동작 방식

NRMS가 하는 일 — 한 줄

사용자가 전에 읽은 기사들을 관심 벡터 하나로 요약하고, 후보 기사 벡터와 내적해서 점수가 가장 높은 후보를 고릅니다. 원 논문: Wu et al., 2019, “Neural News Recommendation with Multi-Head Self-Attention”.

기사 → 기사 벡터 (300차원)→읽은 기사 벡터들 → self-attention → attention pooling → 사용자 벡터→사용자 · 후보 → 5개 중 1등

사용자 벡터 → 점수 → 학습 (네 모드 모두 같음)

  1. 읽은 기사 벡터 [h1, h2, h3, …] (최근 50개까지)에 self-attention(20 head): 기사끼리 서로를 참고합니다. 빙에고르 기사 h2·h3는 서로를 강하게 참고하고, 정치 기사 h1은 따로 남습니다.
  2. attention pooling: 기사마다 중요도를 학습해 가중 평균 → 사용자 벡터 u (300).
  3. 후보마다 점수 = u · 후보 벡터 (내적). 후보 5개 점수에 softmax → 클릭 확률.
  4. 학습: loss = −log P(정답). 정답 c2의 확률이 올라가도록 기사 인코더·사용자 인코더를 같이 학습합니다.
  5. 평가: 점수 1등이 정답이면 Top-1 정답. MRR·nDCG@5·AUC는 정답의 순위로 계산합니다.

데이터와 학습 설정

  • Train 232,874 / Validation half 122,549 / Test 122,668행 (UNI SID 기준 1P4N, Transformer V1과 같은 파일). EB-NeRD는 정답이 공개된 test가 없어서 Validation을 시간순으로 반으로 나눠 뒤쪽을 test로 씁니다.
  • 코드: 정민교 님 MIND NRMS 코드(model.py·dataset.py·train.py)를 그대로 사용. 데이터 읽는 부분만 EB-NeRD에 맞춤(덴마크어 단어 쪼개기, 행 번호 빈칸 허용, 메모리 부족 대응).
  • 설정(원 논문·MIND 실행과 같음): 300차원, 20 head, attention 200, dropout 0.2, Adam lr 1e-3, batch 64, 5 epoch.

남은 과제

  1. c2를 원래 설계대로 사건 단위로: UNI의 c2는 기사별(사건 일치율 74%). EventC2는 100%로 만들었지만 c3 사용 코드가 절반으로 줄고 collision이 52%로 늘었습니다. 둘의 균형이 다음 RQ-VAE의 과제입니다.
  2. 새 사건 c2를 첫 기사 기준으로: 현재는 사건 전체 평균(미래 기사 정보, 5.1%).
  3. Prefix-3 내부 편차: 같은 SID 그룹도 12%는 거의 무관(5장). 입력에 본문 정보를 더하거나 c3 해상도를 높이는 방향.
  4. 추천 방식: SID 생성 + 후보 그라운딩. 생성형 학습은 test 정답의 98% 이상이 새 기사라는 문제를 함께 다뤄야 합니다.
