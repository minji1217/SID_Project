EB-NeRD 파이프라인 전체 흐름

기준: 여민 저장소 main (bcd1168) · 민지 저장소 전처리 브랜치 · 11/18 팀미팅 결정 반영 (z(E) 공간 실험 · 동점 규칙 · validation event_id 용도)
한 줄 요약 — 기사를 4자리 번호(SID)로 바꾸고, 사용자가 본 기사들의 SID 순서를 보고 다음에 클릭할 기사의 SID를 맞히는 구조. 핵심은 c2가 "사건"을 담게 하는 것이고, validation에 처음 나온 기사는 기존 train 사건에 붙어서 그 사건의 c2를 물려받습니다.

train 사건 묶는 방법

연결 조건: 발행 시각 차 ≤ 72h 그리고 IDF 가중 Jaccard ≥ 0.3 → 이어진 기사들을 한 사건으로 묶음.

IDF 가중 Jaccard(A, B) = Σ겹친 개체 idf ÷ Σ합친 개체 idf
기사 AA선수 2.1B구단 1.5런던 0.9 기사 BA선수 2.1C구단 1.8 → 2.1 ÷ (2.1+1.5+0.9+1.8) = 0.33 ≥ 0.3 ✓
확인할 것 — 개체 파일 생성이 main.py에 안 붙어 있음 · 0.3 / 72 / 0.01 하드코딩 → 체크리스트

4. 정한 것 / 논의할 것

이미 정한 것

  • Train C2 = 기사마다 r1 최근접 (교수님 결정, 그대로 유지)
  • validation-only 기사는 발행 시각 순으로, 새 사건 없이 기존 train 사건에만 배정
  • 1차 개체(72h 창 + IDF 가중 Jaccard ≥ 0.3) → 2차 코사인 h(a) vs 사건별 평균 h (창 안 → 없으면 전체). 코사인은 두 실험 모두 항상 h (11/18)
  • z(E)와 사건 C2는 train 학습이 끝난 뒤 train 기사로 한 번 계산, SID 생성 중엔 고정
  • z(E) 공간 쌍 실험 — Q2 KMeans 초기화 입력과 validation-only c2용 z(E)(사건 C2 = Q2 최근접)를 같은 벡터로: 실험 R (잔차, 잔차) = 평균 r1 / 실험 H (인코더, 인코더) = 평균 h. 사건 매칭 코사인은 둘 다 h. 둘 다 돌려 비교 (11/18 팀미팅)
  • 동점 규칙 — 점수가 같으면 event_id 숫자가 작은 사건 (전처리와 동일). 여민 코드의 문자열 정렬은 숫자 정렬로 수정 (11/18 팀미팅)
  • validation event_id는 전처리에서 만들어 RQ-VAE 평가(c2 일관성)의 정답 묶음으로만 씀. RQ-VAE 학습·SID·Transformer엔 영향 없음 (개체 읽기 수정 후 SID 생성도 안 읽음). 컬럼은 유지 (데이터 로더 필수)
  • 1pos4neg에서 정답과 (c1,c2,c3) 같은 오답 제외 (교수님 9/18)
  • 시간 창: EB-NeRD 72h / MIND 24h (MIND는 기사 시각 = 노출 시각)
