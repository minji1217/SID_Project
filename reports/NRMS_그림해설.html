기준은 impression: 같은 사용자도 u가 달라진다

NRMS에는 사용자 ID별로 저장된 임베딩이 없습니다. 매번 그 줄의 history로 u를 새로 계산합니다. history는 사용자마다 시간순으로 늘어나는 running history라서, 같은 사용자라도 impression마다 u가 다릅니다.

  • 1P4N 한 줄 = (impression 1개, 그 impression에서 클릭한 기사 1개). 한 impression에서 2개를 클릭했으면 줄이 2개이고, history가 같으므로 u도 같습니다(평가 기준). 후보만 다릅니다.
  • 학습 중에는 dropout 때문에 같은 history라도 매번 조금씩 다른 u가 나옵니다.
  • V1 Transformer도 같은 1P4N 줄 · 같은 running history를 쓰고 사용자 ID 토큰이 없습니다. TIGER 원 논문은 history 앞에 사용자 ID 토큰을 붙이지만, 우리가 쓴 공개 구현은 쓰지 않습니다.

6. 실험은 어떻게 했나: 절차

5-1 데이터 → 조회 테이블 → 12번 학습 → test

  • 네 모드의 차이는 조회 테이블 하나뿐입니다. 데이터 줄, 후보, 정답, 사용자 인코더, loss, 학습 설정은 전부 같습니다.
  • 섞은 SID 대조군: SID가 있는 기사들끼리 (c1, c2, c3)를 통째로 무작위 교환합니다. 번호 종류와 그룹 크기는 그대로이고, “이 기사에 이 번호”라는 의미만 사라집니다.
  • 후보 순서: 학습 때는 매번 무작위로 섞고(정답 위치를 외우지 못하게), 평가 때는 줄 번호로 고정한 순서로 섞습니다(다시 돌려도 같은 결과).
  • 학습 파라미터 수: E5 652,300 · SID 622,000 · Title 2,498,000. E5와 SID의 차이 30,300은 기사 인코더 차이입니다(E5 Linear 768×300+300 = 230,700, SID 번호표 (26+129+513)×300 = 200,400). Title은 단어 표와 제목용 attention이 더해져 큽니다.

8. recon 모드: 교수님 제안

교수님 말씀(메모) · NRMS의 뉴스 입력은 원래 랜덤 초기화된 뉴스 임베딩이다. 이 자리에 의미가 담긴 임베딩, 즉 RQ-VAE 출력(recon)을 넣어 돌려 봐라.

기사 벡터 다음: 사용자 벡터 → 후보 점수 → loss (세 모드 공통, 단계별)

위 그림의 맨 아래(기사 벡터 300차원)에서 이어집니다. 여기부터는 E5 · recon · SID 모두 계산이 같습니다. 왼쪽 = 하는 일과 식, 가운데 = 크기(실제 모델), 오른쪽 = 4차원 축소 예시로 실제 계산한 숫자(5장과 같은 예시).

왜 돌리나: SID 모드는 RQ-VAE가 배운 의미를 버린다

  • SID 모드는 (21, 117, 485)를 번호(이름표)로만 씁니다. 번호표 E1 · E2 · E3는 랜덤으로 시작해 추천 데이터만 보고 배웁니다. RQ-VAE가 768차원 E5에서 배운 코드북과 decoder는 쓰이지 않습니다.
  • recon 모드는 같은 번호를 RQ-VAE의 코드북과 decoder에 통과시켜 768차원 벡터로 되돌립니다. 정보량은 SID와 같습니다(같은 SID면 같은 벡터). 다른 점은 그 번호가 처음부터 “무슨 내용인지” 아는 상태로 시작한다는 것입니다.
  • 그래서 세 모드를 나란히 놓으면 두 가지를 따로 잴 수 있습니다.
