공개 TIGER를 우리 모델과 같은 설정으로 돌리기

EB-NeRD v2 · 11/26 랩미팅 요청 ②: "공개 TIGER는 하이퍼파라미터가 우리 모델과 완전히 같아야 한다" · 2026-11-26

한 줄 요약 — 데이터 · 평가 · 모델 크기 · 학습 설정은 우리 Transformer와 똑같이 맞췄고, "무엇을 배우나"(손실)만 다르게 남겼다. 그래서 결과 차이는 학습 방식(정답 SID 생성 vs 후보 중 정답 고르기)에서 온다고 말할 수 있다. 공개 모델 코드 구조 때문에 맞출 수 없는 작은 차이가 두 가지 있다(3-2절).

1. 두 모델을 한 그림으로

파란 상자(인코더–디코더)의 크기와 학습 설정, 입력 데이터, 채점 방식은 같다. 학습할 때 오답 후보를 보느냐 마느냐만 다르다.

"공개 TIGER 원래 설정"은 11/23에 돌린 첫 비교(test Top-1 16.7~17.8%)의 설정이다. 이번에는 이 열을 모두 가운데 열 값으로 바꿨다.

3. 다른 것

3-1. 손실: 무엇을 배우나 (핵심 차이, 일부러 남긴 것)

공개 TIGER우리 Transformer
학습 행에서 쓰는 것정답 기사 1개만 (오답 4개는 안 봄)후보 5개 전부
손실정답 SID를 생성하는 CE: c1 맞히기 + c2 맞히기 + c3 맞히기 (teacher forcing)후보 5개 점수 → softmax → 정답 고르기 CE
배우는 것"이 사용자 다음엔 이런 SID가 나온다""이 화면의 5개 중 이게 정답이다"

교수님이 확인하려는 게 바로 이 차이다. 나머지를 다 같게 만들었으니, 결과 차이는 이 학습 방식에서 온다고 말할 수 있다.

3-2. 모델 코드가 달라서 생기는 작은 차이 (하이퍼파라미터가 아니라 구조)

공개 TIGER우리 (여민 코드)
history 기사 하나의 토큰c1, c2, c3 (3개, c4는 모델이 뺌) → 50개 × 3 = 150토큰c1, c2, c3, c4 (4개) → 50개 × 4 = 200토큰
SID 임베딩 표자리마다 512칸 (c1 · c2도 512칸, 남는 칸은 안 쓰임)자리마다 실제 크기 (SID 최댓값 + 1)
출력 head자리마다 512개 중 고르기자리마다 실제 크기 중 고르기
  • c4: 우리 모델은 history에 c4(같은 SID 안 구분 번호)를 넣는다. TIGER는 공개 구현 방식대로 뺀다. 채점에는 둘 다 c4를 안 쓴다.
  • 512칸: TIGER의 c1 head는 25개 대신 512개 중에서 고른다. 안 쓰이는 코드에도 확률이 조금 가지만, 학습하면 거의 0이 된다.
  • 이 둘은 공개 모델 코드를 고치지 않으면 맞출 수 없는 부분이다. 교수님이 "하이퍼파라미터를 같게"라고 하셔서 모델 코드는 그대로 두고, 바꿀 수 있는 설정은 전부 맞췄다. 영향은 작을 것으로 본다.

4. 어떻게 맞췄나 (코드)

  • experiments/eventc2_tiger_reference_v1/run_reference.py: d_model · head · d_kv · d_ff · 층 수 · dropout · SEP · lr 스케줄 · gradient clip을 옵션으로 받게 했다. 기본값은 공개 구현 설정 그대로라, 옵션 없이 돌리면 예전 실행과 같다.
  • head당 차원(d_kv)과 dropout은 공개 모델의 생성자 인자가 아니다. 모델 파일은 고치지 않고, 그 파일이 쓰는 T5 설정의 기본값만 바꿔 넣었다 (d_kv 64 → 32, dropout 0.1 → 0).
  • experiments/v2_yeomin_rerun/7_tiger_reference.sh: CFG=v1이면 위 설정과 학습 데이터(train 1pos4neg)를 넣는다. 결과 폴더는 $V2/tiger/<RUN>_seed42_v1cfg로 따로 둔다.
  • 확인: 이 컨테이너에서 작은 데이터로 1 epoch을 돌려, 저장된 설정이 d_model 256 · head 8 · d_kv 32 · 2층 · dropout 0 · SEP 없음 · history 50 · lr 5e-5 · wd 0 · batch 128 · 스케줄 없음 · clip 1.0인 것을 확인했다 (2026-11-26).
