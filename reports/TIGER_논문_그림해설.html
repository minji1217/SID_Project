TIGER 논문 · 그림으로 보는 학습과 추론

TIGER (Rajput et al., “Recommender Systems with Generative Retrieval”, NeurIPS 2023)가 아이템을 Semantic ID로 바꾸고, 다음 아이템의 SID를 생성하도록 학습 · 추론하는 과정을 그림으로 따라갑니다. 우리 V1과의 차이는 마지막 장에 있습니다.

0. 한눈에

두 단계 · ① 아이템마다 내용 임베딩 → RQ-VAE → Semantic ID(코드 4자리)를 미리 만든다. ② Transformer가 사용자 기록(SID 토큰열)을 읽고 다음 아이템의 SID를 한 자리씩 생성한다. 아이템을 “고르는” 대신 아이템 이름표를 “만들어 내는” 생성형 검색(generative retrieval)입니다.

1. Semantic ID 만들기

  • RQ-VAE는 추천 모델과 따로 먼저 학습하고, 이후 SID는 고정입니다.
  • 같은 (c1, c2, c3)를 받은 아이템이 여러 개면 4번째 자리 c4에 0, 1, 2 … 를 붙여 모든 아이템의 SID를 서로 다르게 만듭니다. 그래서 TIGER는 c4까지 생성해야 아이템 하나가 정해집니다.
  • 우리 UNI SID도 같은 구조(c1 · c2 · c3 + 충돌 순번 c4)입니다. 차이는 c1을 카테고리로 고정하고 코드북 크기가 25 · 128 · 512라는 점입니다.

2. 입력 시퀀스

사용자 토큰

  • 사용자 토큰도 SID 토큰처럼 학습되는 임베딩 하나를 가집니다. 논문: “사용자 ID를 입력에 넣으면 모델이 추천을 개인화할 수 있었다.”
  • 우리 V1 · NRMS · 공개 구현 TIGER는 사용자 토큰 없이 그 시점까지 읽은 기록으로만 사용자를 표현합니다.

3. 학습: 다음 아이템 SID를 정답으로 생성 연습

자리 하나에서 loss를 구하는 순서

“확률을 구하고 softmax”가 아니라, 점수(logit) → softmax → 정답 토큰의 확률 → −ln 순서입니다. 1번 자리(c1)를 예로 들면:

① decoder 1번 자리 출력 벡터 h (128차원)
② logit = W_out · h  → 어휘의 토큰마다 점수 1개     (설명용: 토큰 4개만 표시)
      토큰:    5      12      3      23
      logit: 1.25   0.90   0.50   0.20
③ softmax: P = e^logit / Σ e^logit
      e^logit: 3.49   2.46   1.65   1.22    합 8.82
      P:       0.40   0.28   0.19   0.14    ← 합 1
④ 정답 c1 = 5 이므로 이 자리 loss = −ln P(5) = −ln 0.40 = 0.92
⑤ 2 · 3 · 4번 자리도 같은 방식 → 0.69 · 0.36 · 0.11 → 모두 더하면 2.07
  • 정답 토큰의 확률만 loss에 들어가지만, softmax 분모에 모든 토큰이 들어 있어서 정답 logit을 올리고 나머지 logit을 내리는 방향으로 학습됩니다.
  • 어떤 토큰들 중에서 softmax를 하나: 논문은 T5X 기반이고 어휘가 SID 토큰 1,024개 + 사용자 토큰 2,000개라고만 적고 있습니다. 자리별로 그 레벨의 256개 코드로 제한한다는 언급은 없어서, 보통의 T5처럼 어휘 전체 위의 softmax로 보는 것이 자연스럽습니다. (우리 V1은 자리별 head로 c1 25개 · c2 128개 · c3 512개 중에서 softmax합니다.)
  • 사용자 기록 [아이템1, …, 아이템n]에서 “앞 아이템들을 보고 다음 아이템의 SID 맞히기” 예시를 만들어 학습합니다(어느 시점들을 예시로 쓰는지는 구현마다 다름).
  • loss = 정답 SID 4자리 각각의 −ln 확률. 위 예시처럼 다 더하면 −ln P(아이템) = 2.07이 됩니다(자리별 확률의 곱 = 아이템 확률).
  • 오답 아이템을 직접 보여 주지 않습니다. 대신 자리마다 softmax가 “정답 코드 vs 나머지 모든 코드”를 비교하므로, 사실상 모든 다른 아이템이 오답인 학습입니다.

4. 추론: beam search로 SID 생성

  • 정답을 모르니 decoder 입력이 모델이 방금 만든 토큰입니다: [BOS] → [BOS, 5] → [BOS, 5, 23] → [BOS, 5, 23, 55].
  • 생성을 실제 존재하는 SID로 제한하지 않아서, 없는 조합(invalid ID)이 나올 수 있습니다. 논문은 그 비율이 작다고 보고하고, beam을 넉넉히 잡아 invalid를 걸러 냅니다.
  • 새 아이템도 SID가 있으므로, 생성한 SID와 앞 3자리가 같은 새 아이템을 후보에 넣는 방식으로 cold-start 추천을 합니다(7장).
  • 논문은 invalid가 나오면 앞자리(prefix)만 맞는 아이템을 찾는 방법을 향후 과제로 제안합니다.
  • beam 크기: 논문에는 없습니다. 공개 구현(EdoardoBotta, modules/model.py · configs/decoder_amazon.gin)은 beam 10(= Recall@10의 K)이고, 논문과 세 가지가 다릅니다: ① 자리마다 beam별로 코드 64개를 확률에 따라 샘플링해 후보로 씀(256개 전부 X) ② 실제 SID에 없는 앞자리는 점수 −∞로 막아 invalid가 나오지 않게 함(제약 decoding) ③ 자리별 출력 head(레벨마다 256개 중 softmax).

4-1. 학습 vs 추론: decoder에 무엇이 들어가나

decoder 입력계산앞자리를 틀리면
학습정답 SID [BOS, c1, c2, c3]4자리를 한 번에 (causal mask)다음 자리 입력은 그래도 정답
추론모델이 만든 토큰 [BOS] → [BOS, ĉ1] → [BOS, ĉ1, ĉ2] → …한 자리씩 순서대로, beam B개 · encoder는 한 번만틀린 토큰이 그대로 다음 입력 → 뒤 자리도 틀어짐

완성된 SID는 “SID → 아이템” 조회표로 아이템으로 바꾸고, 없는 SID는 버립니다. 학습 때 본 적 없는 “자기가 만든 틀린 앞자리”를 추론 때 처음 보게 되는 차이를 exposure bias라고 부릅니다.

5. 평가

TIGER는 “전체 아이템 중 top-K 안에 정답이 있나”(검색 문제)를 보고, 우리는 “후보 5개 중 1등이 정답인가”(순위 문제)를 봅니다. 그래서 우리 TIGER 실험은 학습만 TIGER 방식이고 평가는 후보 채점으로 바꾼 것입니다.

“정답이 목록 안에 들어 있기만 하면” 맞은 것이 Recall, 순위가 높을수록 더 쳐주는 것이 NDCG입니다. 예: Beauty Recall@10 0.0648 = 사용자의 약 6.5%가 다음에 산 상품이 top-10(상품 12,101개 중) 안에 있었다는 뜻입니다.

invalid는 top-K 목록 안에 섞여 있다

  • 논문 Figure 6의 invalid 비율 = beam search로 만든 top-K개 SID 중 실제 아이템이 없는 SID의 비율입니다. 예: top-10 중 9개는 실제 아이템, 1개는 없는 SID → 10%. 사용자 평균으로 top-10 기준 약 0.1 ~ 1.6%, top-20 기준 Sports 약 0.3% · Beauty 약 1.3% · Toys 약 6% 이하(그래프 판독).
  • 즉 목록의 대부분은 실제 아이템(valid)이고, 가끔 invalid가 하나쯤 섞입니다. invalid SID는 어떤 아이템과도 같지 않으므로 그 자리는 자동으로 “틀림”입니다.
  • 논문은 “invalid를 생성하는데도 SOTA 성능”이라고 쓰고, 대처는 “beam을 키우고 invalid를 걸러 top-10을 채울 수 있다”고만 적습니다. 그래서 Table 1은 invalid가 섞인 목록 그대로 채점한 것으로 읽히지만, 걸러 내고 다시 채웠는지는 명시되어 있지 않습니다.
  • 10개가 모두 invalid인 경우의 처리도 논문에 없습니다. beam을 키워 K개를 채우는 것이 논문이 제시한 방법이고, 그래도 모자라면 목록이 짧아져 맞힐 기회가 줄어들 뿐입니다. prefix matching(앞자리가 같은 아이템으로 바꾸기)은 향후 과제로만 언급됩니다.

④ cold-start 실험

Beauty에서 test 아이템 5%를 train에서 빼 “처음 보는 아이템”으로 만들고, 모델이 생성한 SID와 앞 3자리가 같은 새 아이템을 후보에 넣습니다(새 아이템 비율 상한 ε). ε ≥ 0.1에서 의미 임베딩 KNN보다 높은 Recall을 보고합니다.
